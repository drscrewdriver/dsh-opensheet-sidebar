# Список изменений — dsh-opensheet-sidebar

## 1.0.1 — 2026-09-25

Дедупликация предупреждений предохранителя: при срабатывании одного измерения выходит только одно предупреждение. Дубли в 1.0.0 возникали из-за того, что потолок строк и бюджет предпросмотра каждый выдавали своё предупреждение `rows`.

> **Запись о публикации (2026-09-25)**: npm `dsh-opensheet-sidebar@1.0.1`, dist-tags `latest` + `dsh-0.1.5`; 49 files / 98.8 kB, shasum тарбола `1862528750612980122ffc3d31f31eb05eb1bf7d`.

### Исправлено

- **Одно и то же измерение больше не предупреждает дважды**: потолок строк и бюджет предпросмотра теперь делят один флажок, `finalize()` доопределяет `found`, поэтому единственная строка несёт сразу kept/limit/found вместо рендера двух почти одинаковых баннеров. Новое утверждение: **ровно одно предупреждение на каждую причину**.
- **Объявлено поле `repository`**, указывающее на `drscrewdriver/dsh-opensheet-sidebar`. Подборки связывают npm-пакет с репозиторием только когда опубликованный пакет сам ссылается на репозиторий; у 1.0.0 этого поля не было, потому и не были связаны.

### Добавлено

- **Набор настоящих xlsx-фикстур** (`scripts/make-xlsx-fixtures.py`, фиксированное зерно случайности): openpyxl создаёт шесть настоящих книг, каждая срабатывает ровно по одному пути предохранителя; `scripts/report-fixtures.mjs` прогоняет их **собственным ридером плагина** и печатает прочитанное. Именно он и вскрыл этот дубль, а заодно покрывает путь пользовательских форматов дат, недоступный синтетическим zip-фикстурам (настоящий вывод openpyxl → 2026-01-08).

### Тесты

- 25 утверждений (14 csv + 11 xlsx), код выхода 0; отчёт по фикстурам показывает ровно одно предупреждение на файл.

## 1.0.0 — 2026-09-22

**Переименование идентичности пакета: `dsh-csv-sidebar` → `dsh-opensheet-sidebar`.** Функционально полностью совпадает с 0.3.0, поведение не меняется, меняются только идентичность и отображаемое имя.

> **Запись о публикации (2026-09-22)**: npm `dsh-opensheet-sidebar@1.0.0`, dist-tags `latest` + `dsh-0.1.5`; 49 files / 97.2 kB, shasum тарбола `88b7fed194c15cd6cd59c1d87e69ae9e8503b5aa`. После публикации тарбол был обратно вытянут из registry для перекрёстной проверки: `lib/client.js` побайтово совпадает со сборкой репозитория (`43CF34FDCB65…`), id модуля внутри бандла = `dsh-opensheet-sidebar`. Профиль мигрировал с пина `github:` на эту npm-версию (spec записана на диск точным значением `1.0.0`).

Имя — каламбур: **Open** (открыть) ＋ **Open** (открытый стандарт) — одно слово покрывает и «открыть таблицу», и «читать таблицу, не завися от проприетарных библиотек». Каламбур живёт только в имени; функциональные поля остаются строго буквальными (`exts` получает только реальные расширения).

> След процесса именования: сначала устоялось множественное `opensheets`, за минуту до публикации исправлено на единственное `opensheet` (имя собственное в единственном числе больше похоже на бренд и крепче связывается с семейством OpenDocument). Эта запись описывает итоговую идентичность.

### Изменено

- Имя пакета / имя репозитория / `dsh.plugin.json#id` / row id+name в `cordis.patch.yml` → `dsh-opensheet-sidebar`. **Эти места обязаны быть синхронны**: id клиентского модуля выводится из `package.json#name`, а `name:` строки — то, по чему client-modules находит манифест пакета; пропустить одно место = хостовая строка есть, клиентская половина молча не загружается (тот самый род отказа, что в 0.1.0).
- Переименованы и префиксные id: `TAB_ID` / `VIEWER_ID` / `XLSX_VIEWER_ID` / id тега стилей / пространство имён locale.
- Отображаемое имя вкладки боковой панели: `CSV` → `Sheets` (zh: `表格`). Заголовки просмотрщиков остаются описательными (`CSV table` / `Spreadsheet table`) — сказать, что это, по типу файла, а не навешивать имя продукта.
- Скачок до 1.0.0: для потребителей это ломающее изменение (меняется идентичность пакета), а не минорная версия.

### Миграция (старая идентичность → новая идентичность)

1. `dsh plugin --profile <p> add github:drscrewdriver/dsh-opensheet-sidebar#<sha>`
2. `dsh plugin --profile <p> remove dsh-csv-sidebar` — `reconcilePlugins` сам вычеркнет старое имя из `dsh.profile.bundles`
3. В `cordis.patch.yml` профиля заменить строку `- id: dsh-csv-sidebar` на новый id (патч по несуществующему id — беззвучная пустая операция; оставленная лишь собьёт с толку идущих следом)
4. Перезапустить хост один раз

> Побочный эффект: выключатель включения/отключения better-sidebar ключуется по `tabsEnabled[<id>]`; id сменился → прежние выключатели пользователя возвращаются к значениям по умолчанию. Старый репозиторий `drscrewdriver/dsh-csv-sidebar` сохранён, но больше нигде не упоминается.

## 0.3.0 — 2026-09-22

Поддержка xlsx (с **переключением листов**). Ноль зависимостей: распаковка zip идёт через нативный браузерный `DecompressionStream('deflate-raw')`, XML — прицельным сканированием вместо универсального парсера.

### Добавлено

- **Просмотрщик книг**: `.xlsx` / `.xlsm` открываются таблицей, сверху ряд вкладок листов позволяет переключаться; скрытые листы (`state="hidden"`) показаны приглушённо, по умолчанию автоматически открывается первый видимый лист.
- **Ридер xlsx** (`src/client/xlsx.ts`): разбор центрального каталога zip (корректная обработка случая data-descriptor, размеру верят только из центрального каталога) → список листов из `xl/workbook.xml` → `_rels` rId→part → `sharedStrings.xml` (склейка run'ов форматированного текста) → `styles.xml` (`cellXfs` → numFmtId → распознавание дат) → распаковка по требованию ровно одного `worksheets/sheetN.xml`.
- **Обработка ячеек**: общие строки / встроенные строки / кэшированные значения формул (`t="str"`) / логические / ошибки / числа; **пропуски столбцов** восстанавливаются по `r="C3"` (отсутствующий столбец не сдвигает следующий); серийные номера дат переводятся в читаемые даты по эпохам 1900/1904.
- **Две барьерные проверки контейнера** (прежняя проверка размера для zip была равна отсутствию защиты):
  - **заявленный объём распаковки** сверяется до любого действия распаковки (заголовок zip можно подделать, отсюда детерминированный отказ на входе);
  - **потоковый байтовый бюджет распаковки** как страховка, счёт идёт по ходу распаковки, при превышении — немедленный `cancel()`.
  Если один лист сам по себе превысил лимит, блокируется только этот лист; соседние листы остаются читаемыми.
- Новые тексты предупреждений `inflated-bytes` / `sheet-bytes` / `container-error` (zh/en).
- **Тесты**: `tests/xlsx.test.mjs` на месте строит настоящие zip-фикстуры (с CRC32 и корректным центральным каталогом) — список листов и метки скрытости, общие строки, ячейки-даты, пропуски столбцов, переключение между листами, zip-бомба с поддельным объёмом, вход не-zip; 11 утверждений, код выхода 0/1.

### Исправлено

- **Плейсхолдеры предупреждений больше не торчат голыми**: при исчерпании бюджета предпросмотра (строка 201) предупреждение генерировалось, когда `found` ещё неизвестен, и интерфейс показывал прямо `共至少 {found} 行`. Теперь `finalize()` доопределяет фактически подсчитанное число строк.
- Новая **проверка целостности плейсхолдеров** (по одной в каждом тестовом наборе): обходит предупреждения, реально порождаемые каждым измерением, и требует, чтобы каждый `{name}` шаблонов zh/en находился в detail, иначе красный свет. Такие баги больше не будут находиться невооружённым глазом.

### Изменено

- Два новых порога в конфигурации предохранителя: `maxInflatedBytes` (по умолчанию 64 MB), `maxSheetBytes` (по умолчанию 32 MB).
- Полоса состояния: книга показывает метку с именем листа, вместо ошибочного «разделителя».
- Просмотрщик xlsx идёт через `fetchStrategy: 'custom'` + хостовый маршрут `/sidebar/file` за сырыми байтами (`fsRead` для бинарного отвечает только `head`, для разбора непригодно); ограждение путей рабочего пространства остаётся на стороне хоста.

### Пока не поддерживается

- `.xls` (Excel 97-2003 BIFF8) и старые форматы WPS `.et` / `.wps` / `.dps`: все — OLE2-составные документы, реализация с нулевыми зависимостями дорога (пришлось бы самому строить разбор CFB + BIFF). Покрытие означает подключение SheetJS (~1 MB, причём версия на npm больше не развивается), вразрез с принципом нуля зависимостей — оценивается отдельно.

## 0.2.0 — 2026-09-22

Переписывание в стандартный формат. Клиентская половина 0.1.0 не соответствовала контракту клиентских модулей DSH: установленная в профиль, она **не загружалась** (без ошибок, без записей); эта версия переделала интеграционный слой по стандарту plugin-framework.

### Исправлено (интеграционный слой — все первопричины «не показывается»)

- Клиентский артефакт становится CJS-замыканием `window.__ModuleLoader__.load({ id, factory })`, фабрика которого экспортирует `apply` + `inject` (раньше — ES-модуль + `activate()`, таблица модулей всё отбрасывала).
- Точка стыковки регистрации переходит с `ctx.sessionProjections` на `ctx.betterSidebar.registerFileViewer / registerTab` (первая — хостовый реестр проекций, а не UI-стык боковой панели).
- Добавлено декларативное `inject = ['betterSidebar', 'locale']`: apply ждёт лишь готовности двух сервисов cordis; порядок регистрации больше не влияет на результат.
- Все установки идут через `ctx.effect(fn, label)`; при HMR / отключении убирает disposer (тег стилей, словари, два дескриптора).
- Дописаны метаданные: `package.json#dsh.bundle.patch` + `dsh.client.platform/inject`, списки `exports` / `files`, `screenshots.json`, `assets/`, `tsconfig*.json`.
- Peer-потолок унифицирован до `<0.2.0-0` — обход ловушки сравнения semver-prerelease; `dsh-better-sidebar` / `react` помечены optional.

### Добавлено

- **Точка стыковки просмотрщика файлов**: `.csv/.tsv/.psv` (priority 50, `fetchStrategy: 'fsRead'`) попадают в список «просмотр файлов» GUI, включаются/выключаются в настройках карточки Side; читает хост, ограждение путей остаётся на его стороне.
- **Строительный заслон загрузки**: реально грузит артефакт через `node:vm` + заглушку `window.__ModuleLoader__`, проверяет `id`, `apply`/`inject` у `factory()` и отклоняет запросы встроенных модулей Node.
- **12 ключевых утверждений** (`npm test`, код выхода 0/1): кавычки и экранирование RFC 4180, эвристика разделителя, четырёхмерный предохранитель, метка усечения хостом, пустые строки и пустой документ.
- Собственное i18n-пространство имён `dsh-csv-sidebar` (zh/en), при отсутствии `locale` — откат ко встроенному английскому словарю.
- Стили на семантических токенах `--dsw-alias-*` (больше никакой зависимости от несуществующих переменных вроде `--border-color`).

### Изменено

- **Ноль runtime-зависимостей**: удалён PapaParse, заменён локальным сканером, понимающим кавычки (RFC 4180, поля через границы строк поддерживаются); бандл экстернализует только React (43 KB).
- Сборка переведена с Vite на esbuild с двумя входами (`lib/index.mjs` + `lib/client.js`), добавлены tsc-декларации типов.
- Семантика предохранителя ужесточена: при исчерпании бюджета `previewRows` — **явное повышение до предупреждения `rows`** (больше не молча показывает только первые 200 строк); две ветки `OK` в `finalize()` слиты.
- Исходники по стандартной структуре переехали в `src/client/`; хостовая половина выделилась в самостоятельный `src/index.ts`.

### Удалено

- `vite.config.ts`, зависимость `papaparse`, старые плоские компоненты `src/*.tsx` и неверную запись поля `main`, указывавшую на `./lib/client.js`.

## 0.1.0 — 2026-09-22

Первый прототип: `demo.html` из `npm run dev` проверил на вид табличные взаимодействия и четырёхмерный предохранитель, затем всё было обёрнуто в плагин. **Плагиновая обёртка этой версии в DSH не загружается** (см. Исправлено в 0.2.0).
